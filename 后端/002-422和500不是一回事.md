# 422 和 500 不是一回事：一个是框架在说话，一个是你

**症状**

```json
// 请求体少了字段 / 类型不对
422 Unprocessable Entity
{"detail":[{"loc":["body","package"],"msg":"Field required",...}]}

// 代码自己炸了（比如漏 import）
500 Internal Server Error
```

**为什么**

- **422** = 框架替你挡在门口。请求长得不像你声明的那个模型（少字段、类型错），它在进你函数之前就退回去了。**你一行校验代码都没写。**
- **500** = 请求进来了，你的函数里抛了异常，框架没接住。

**解法**

- 看到 **422**：读响应 body 里的 `detail`，它直接告诉你哪个字段、错在哪。
- 看到 **500**：**别盯浏览器**，看终端里那段 traceback，最后一行就是元凶（`NameError`、`AttributeError`……）。

**记住**

> **422 是"你给的东西不合形状"，500 是"我的代码不合逻辑"。**
> 前者改请求，后者改代码——先分清是谁在说话。
